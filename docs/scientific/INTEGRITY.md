For an authorised reproduction, retain a restricted manifest of actual weight *and auxiliary file* revisions and hashes, complete environment lock, source revision and any dirty diff, effective decoding settings, approved reference version, source audio and prediction hashes, experimental order, timing policy, failures and raw records. The released examples supply a subset of these ingredients. Recomputing scores from stored strings checks scoring. Running the identical inputs twice in separate directories checks repeatability. Independent reproduction additionally requires another operator or environment to reconstruct the experiment and document deviations.

## Efficiency and duration

The scheduler times model loading around the loading callback and session opening. Optional warm-up has a separate interval. Its recording timer starts before the running callback and ends after inference returns and the stop callback is checked. The timed path includes audio/reference integrity checks before and after the request, worker communication, backend audio decoding and inference, text assembly, and optional monitor entry, exit and summary. Startup duration decoding, checkpoint scoring, export and cleanup fall outside that interval. Cache state and first-use preparation can affect loading. Asynchronous kernels may require device events or explicit synchronisation for an independent GPU-only timing experiment. The implementation measures host elapsed time to a returned prediction.

For recording \(j\), \(r_j=t_j/d_j\), where \(t_j\) is recorded inference-request elapsed time and \(d_j\) is decoded source duration, both in seconds. Mean and median recording RTF describe valid recordings with equal recording weight. The aggregate is \(\sum_j t_j/\sum_j d_j\). Loading plus inference counts each eligible model session's loading time once. Complete experiment wall time also includes startup, warm-up, scoring, reporting and teardown. Report the cohort and denominator beside each measure. See the [benchmark methodology](BENCHMARK_METHODOLOGY.md).

The resource sampler reads the first GPU row returned by nvidia-smi and records system-wide utilisation, memory and temperature. psutil provides host CPU and used RAM. Polling waits 0.5 s *after* collection, so actual spacing includes command and scheduling overhead. Sampled maxima depend on sampling cadence and competing processes. Source RAM fields use bytes divided by 1,048,576, i.e. MiB, although the implementation labels them MB. GPU fields use the numeric output of a unit-suppressed CLI query. Verify the installed driver's unit-bearing output before converting values for a manuscript. Preserve missing data and effective sample count. A repeated run with the monitor disabled can estimate monitoring overhead. [ResourceMonitor](../../redscribe/benchmark/benchmark_resources.py).
